= Changelog

All notable changes to this crate are recorded here. The format follows
https://keepachangelog.com/en/1.1.0/[Keep a Changelog] and the versions
follow https://semver.org/spec/v2.0.0.html[Semantic Versioning].

== 0.3.3 - 2026-04-18

=== Added

- `MAX_FIX_RECONNECT_DELAY`.

=== Changed

- FIX 4.4: a configuration shortens a reconnect delay above one hour to one
  hour.
- Examples: outside demo the token refresh example rotates the pair only
  under `BROKER_EXAMPLE_ALLOW_LIVE=yes`. The test that scans the sources
  holds every example to an allowlist of library items, refuses a `use` that
  renames or globs and pins the access level each example asks for.
- Build: the test targets that need a protocol declare its feature, so that
  `cargo test` builds with any set of features.

=== Fixed

- FIX 4.4: a reject (3) or a business message reject (j) whose header cannot
  be read is counted and no longer answered with a reject. A reject sent for
  a header that cannot be read names the type of the message (372) when its
  bytes show one.
- Documentation: the rejects, the reconnect delay and the limits of the
  guard of the examples match the behaviour; the README lists the known
  limitations.

== 0.3.2 - 2026-04-17

=== Added

- `ConfigError::TooLong` and `MAX_FIX_HEARTBEAT`.
- `BROKER_EXAMPLE_ALLOW_LIVE` for the examples: `read-only` or `yes`.

=== Changed

- FIX 4.4: a configuration refuses a heartbeat interval above one hour.
- Open API: a heartbeat interval, a silence allowed or a time allowed for a
  response above thirty years is never due; it used to end after thirty
  years.
- Examples: every example, the read-only ones included, takes its
  configuration and its client from one allowlist guard and runs against
  demo only unless `BROKER_EXAMPLE_ALLOW_LIVE` permits more. A test scans
  the sources for a way around the guard.
- Live tests: `fix_live` refuses a sender identifier that does not start
  with `demo.`; its heartbeat watch accepts heartbeats and test requests
  only.

=== Fixed

- FIX 4.4: a wait the clock cannot hold, such as a timeout of
  `Duration::MAX`, is never due; the session task no longer spins once a
  year has passed.
- FIX 4.4: a readable message in turn that is refused is answered: an
  unsupported type with a business message reject (j, reason 3), a body
  that cannot be read with a reject (3). A reject that cannot be read is
  never answered.
- Documentation: order kinds over FIX and `OrderKind::StopLimit`, a logout
  or a resend request ahead of its turn, the heartbeat bounds, the rejects,
  the errors a call returns, the live tests and the headers of the examples
  match the behaviour.

== 0.3.1 - 2026-04-13

=== Changed

- FIX 4.4: `encode` refuses a body that holds a tag of the standard header
  (34, 35, 43, 49, 50, 52, 56, 57, 122), as it does the tags of the framing.
- `ServerError` prints its account as masked in `Debug` output; the field
  stays readable.

=== Fixed

- FIX 4.4: a message whose header cannot be read but whose bytes are intact
  is counted, reported as `Event::Unparsed` and answered with a reject (3),
  so that it no longer forces a resend and then a reconnection.
- FIX 4.4: a heartbeat is sent when the interval since the last message sent
  ends, not at the next tick of a timer after it.
- FIX examples refuse an account that is not a demo one before logon.
- Tests: an order whose write fails is asserted to have an unknown outcome
  over both protocols; the keep-alive timing is asserted on a paused clock.
- Live tests: all output passes through one redacting function; the refresh
  test asserts the end of the session opened with the old token; the
  heartbeat watch accepts every administrative message.
- Documentation: the two meanings of `Closed` over FIX, the fate of messages
  ahead of their turn, the tests that need `BROKER_ENV_FILE` and the list of
  `tracing` events match the behaviour.

== 0.3.0 - 2026-04-10

=== Added

- FIX 4.4: tag-value codec and typed messages.
- FIX 4.4: session with logon, heartbeats, test requests and typed rejects.
- FIX 4.4 quote session: spot price and depth streams, security list.
- FIX 4.4 trade session: new order single with typed execution reports;
  order cancel and replace with typed cancel rejects; order status, mass
  status and position reports.
- FIX 4.4: reconnection, resend requests and gap fill; no order is sent
  again.
- `force_reconnect` on the Open API connection and on the FIX client drops
  the connection and starts a reconnection as a loss would.
- One runnable example per group of requests for both protocols, under
  `examples/open_api` and `examples/fix`.
- Crate and module documentation: configuration, connection lifecycle,
  error handling, streams, rate limits, logging, testing and protocol facts;
  a README that covers features, both protocols, the examples and the
  environment variables.
- This changelog.

=== Changed

- The transport shared by both protocols (`Connect`, `Plain`, `Tls`) moved
  to `common::transport`; `open_api::transport` re-exports it.

=== Fixed

- Open API: events by which the server ends the authorisation of an account
  or of the application surface as a typed event and a typed error, and
  nothing of an ended session is replayed.
- Open API: the slippage of a stop-limit order is bounded before the order
  is sent.
- Live tests: margin call and cash flow checks fail on empty input;
  leftovers are swept over a fresh connection with polling; account
  identifiers stay out of the test output.

== 0.2.0 - 2026-03-29

=== Added

- Open API trading: market orders that are never sent twice; limit and stop
  orders with expiry and protection; stop-limit orders as a stop price with
  slippage.
- Open API trading: amendment of pending orders and of the protection of
  positions; cancellation of pending orders; closing of positions in whole
  or in part.
- Open API: reconcile of positions and orders as typed values.
- Open API: stream of execution and order error events.
- Open API account data: trader balance, currency, leverage and account
  type; deal and order history by time range; margin events, margin calls
  and cash flow history.

== 0.1.0 - 2026-03-12

=== Added

- Crate skeleton with a pinned toolchain and lint rules; features `open-api`,
  `fix` and `logging`.
- Configuration builders with demo and live constructors; error types that
  preserve the error codes of the server; typed identifiers and exact
  decimal prices and volumes.
- Open API: vendored proto files and generated messages; TLS transport with
  length-prefixed framing; connection task with correlation of requests and
  heartbeat.
- Open API: application and account authorisation; token refresh over the
  connection and over HTTPS.
- Open API: reconnection with backoff, renewed authorisation and replay;
  pacing of requests and retry on limit errors with backoff.
- Open API market data: assets, symbols and symbol details; spot quote
  stream; depth stream with a rebuilt order book; trendbar history and live
  trendbar stream; tick history.

=== Fixed

- Open API: stream state is reset on the loss marker; events lost by a slow
  reader are reported as a typed error.
- Open API: socket writes are bounded and a server that stays silent is
  given up; the default period of silence follows the cadence of the server.
- Open API: the replay set is read at each step of the restoration; request
  and replay identifiers come from one counter.
- Open API: every tick of a paged range is returned once, or the request
  fails with a typed error.
- Open API: deadline arithmetic saturates, channel capacities are clamped
  and the conversion of the system time is checked.
